# 通用社媒贴文文案

把当前项目的素材事实变成自然、逐条有差异的发布文案，并保留标签和参考文案的依据。适合 TikTok、Instagram，也可按用户明确指定的平台调整；不承诺未经核查的平台规则或流量效果。

本技能由 Codex 直接阅读、研究和生成，不附带命令行生成器，不依赖 PixVerse、旧版脚本、固定模型或指定 API 服务。新项目配置和用法见 [说明文档](references/USAGE.md)；批量输入、证据及交付字段见 [数据约定](references/DATA_CONTRACT.md)。

## 先确定当前项目规则

- 先读当前项目适用的 AGENTS、说明及用户指定的品牌资料。用户本轮明确要求优先；未被本轮覆盖的已确认项目规则继续有效；项目配置补充空缺；本技能默认值最后使用。遇到会改变含义的规则冲突先指出，不静默覆盖。
- 如有用户指定的配置文件，读取该文件；否则只在当前项目根目录查找 `post-copy.project.json`。没有也可以直接执行，不自动创建配置，不到其他项目寻找可复用品牌规则。需要保存配置时使用 [配置模板](assets/project-profile.example.json)。这些字段是给 Codex 读取的约定，不是旧版脚本参数。
- 每条素材至少要明确发布平台、目标语言及可用于写作的素材事实。目标市场、账号定位、品牌词和禁用表达按已有资料补充。可根据明确的平台链接识别平台，但不把国家直接等同于语言；无法可靠确定时询问受影响项，继续处理独立完整的记录。
- 默认使用文字 brief、用户提供的参考文案和网页文字/元数据。不下载或分析视频、音频、图片，除非用户明确要求。成片未核实时，不把策划里的预期结果写成已发生事实。
- 保留源文件。仅生成文案、研究记录及用户要求的本地交付物；发布到社交平台或发送给他人需另有明确授权。

## 执行方式

1. **读取并映射。** 单条文本直接处理；批量文件先查看工作表、表头、筛选范围和已有发布字段。需要精确保留表格结构时，使用当前环境适用的表格工具或技能。保留源工作表、原行号与 ID；缺 ID 时生成仅本次稳定且可回溯的 ID。详见数据约定。
2. **检查事实冲突。** 当前素材、旧 Caption、样片可能属于不同版本。例如旧文案写婴儿，新 brief 写成年人跳舞：不要直接复用旧稿；标记冲突，能明确最新素材时按其写草稿，否则停止该条最终拼接并说明缺失信息。热点原片人物也不等于本条二创素材人物。
3. **分组研究。** 按平台、市场、语言和明确的热点/主题身份分组，复用该组研究，不复用最终文案。不要仅因同一创作者或名字相似就合并。用户说“第一个热点”时取该热点所有适用记录，而非只取第一行。非热点内容按主题处理，不为它编造热点名。
4. **按需查证。** 用户要求热门/近期标签、提供网页参考或需要当前平台限制时，使用可用搜索/连接器读取来源；优先用户给的样片及同平台、同热点、同市场的帖子。普通创意草稿可仅基于用户文字，但必须如实注明未外部验证。访问受阻时记录 URL、时间和可见范围，改用其他公开文字来源；同一路径合理尝试后仍失败即降级，不反复重试。没有联网能力也可完成有标记的草稿。
5. **逐条写作。** 直接用目标语言写 Caption，再忠实译为简体中文；翻译语言可配置或由用户取消。同组在开头、句式、视角、节奏或互动方式上有实际变化，不能只替换人物名字。问句、冷幽默、反差、短句等只是可选形式，不强套固定模板。未经资料支持，不补造动作、台词、结局、成绩、背书或功能效果。提及人物姓名要与本条素材一致；默认不生成 `@` 账号或第二套带 `@` 的版本。
6. **选择标签。** 按当前项目规则组装标签；品牌、产品词只在资料明确支持或用户指定时使用。没有配置时目标为最多 5 个相关且有依据的标签，允许少于 5 个；不默认加任何品牌词、`#fyp` 或固定末位标签。明确要求“恰好 N 个”时改用精确数量规则。保留标签当地语言拼写，逐条去重并关联来源。指定标签与动态标签的证据分别记录，不把品牌要求伪装成热门依据。
7. **审阅并交付。** 检查事实、语气、译文、Emoji 一致性、标签数量及排序、近似重复、来源归属和状态。默认 Emoji 0–2 个，随语气自然选择；项目可改为 1–2 个或禁用。保持译文中的 Emoji 与原 Caption 一致。批量按数据约定导出，重开核对文件、记录数及非英文字符，最后报告完成数、需复核数、失败数和具体原因。

## 证据与状态

证据等级表示“看到了什么”，不是标签热度排名：

- `observed_post`：实际读到相关平台帖子的 Caption 或标签；保存帖子 URL、观察时间及可见原文要点。
- `search_evidence`：仅搜索摘要、第三方索引或背景页；不能当作原帖全文、同热点热门文案或可靠互动量。
- `user_supplied`：用户文件、文字或用户粘贴的原文；记录文件/工作表/行号或消息出处，不能自动声称平台已验证。
- `project_required`：用户或项目明确指定的品牌/固定标签，记录对应规则；无需假造网页来源。
- `unverified`：只有候选词或推测，缺少上述依据；只列为候选，不混入最终发布标签。

同热点文案、创作者风格、源片背景必须区分。高播放参考要有可核实指标及观察时间；无数据就不称“高播放”。观察到有人用某标签不等于当前热门。平台范围热度判断还需同平台、明确时间窗、可比指标等证据，不足时直接写“热度未验证”。

- `SUCCESS`：本条素材事实无未解决冲突，输出符合要求，动态标签有相关原帖依据；仅使用指定固定标签或无需标签时，不强求外部证据。表示本次检查通过，不等于已发布或保证流量。
- `NEEDS_REVIEW`：可用草稿完整，但标签只有用户文字/间接证据、成片事实待核实、参考受阻或其他需要人判断的问题；附具体原因。默认不因无法验证热度而丢掉有依据的相关性草稿。
- `FAILED`：缺少必要平台/语言/素材事实、无法消除核心事实冲突、输出质量检查仍失败，或明确精确标签数无法满足。保留可用草稿及失败原因，最终 `post_text` 留空。一个失败不阻断其他记录。

数量或排序不满足硬性要求时不得标为成功。所有标签均为指定词、未要求热度且事实完整的内容，可直接按规则校验；不为证明指定词“存在”额外研究。只有待用户判断、且可安全形成草稿的问题使用 `NEEDS_REVIEW`；会改变主体或事件真伪的未决冲突使用 `FAILED`。

## 默认交付

单条在对话中给 Caption、中文翻译、Hashtag、可复制贴文和状态；把复核说明放在贴文之外。批量默认每条一份文案，输出 `post_copy_result.xlsx`、UTF-8 BOM CSV、`research_evidence.xlsx` 与 `run_report.md` 到当前项目下独立的新目录；用户要求的格式/数量优先。文件生成能力不足时提供可实际交付的 CSV/文本并说明缺项，不伪称已生成 Excel。

最终贴文只拼接目标语言 Caption 与选定标签，不混入中文翻译、来源、状态或写作标签。批量结果保留原始记录供追溯。详细字段和拼接规则见 [数据约定](references/DATA_CONTRACT.md)。
